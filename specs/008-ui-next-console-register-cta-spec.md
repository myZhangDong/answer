# 008 `ui-next` 注册环信 CTA 与 Console 跳转埋点 Spec

## 1. 背景

当前 `ui-next` 前台里已经存在两类“注册/CTA”入口，但口径并不一致：

- 首页 Header 右侧已有“注册环信”按钮，但跳转地址仍是 `https://console.easemob.com/user/register`，没有带上社区来源参数
- 文章详情、视频详情、开源项目详情底部仍复用 `CtaBanner` 的“登录后台发布 / 进入后台管理”逻辑，和当前内容门户的对外导向不一致
- 这些入口当前没有统一的前端点击埋点出口，后续无法按位置区分注册导流效果

结合本轮需求，需要把前台公开注册导流统一收口为：

- 固定跳转到 `https://console.easemob.com/user/register?from=community`
- 首页 Header 右侧注册入口点击时补埋点
- 文章、视频、开源项目详情页底部 CTA 全部改成面向环信云平台注册的营销文案，并在点击时补埋点

这与之前“前台 CTA 改为后台发布导向”的阶段性做法不同，因此需要拆出 `008` 独立规格，避免后续继续按旧口径回退。

## 2. 目标

### 2.1 产品目标

让 `ui-next` 前台公开注册 CTA 全部围绕“注册环信智能互动通讯云平台”统一表达。

第一阶段必须满足：

- 首页 Header 右侧注册入口点击后跳转到 `https://console.easemob.com/user/register?from=community`
- 文章详情页底部 CTA 不再显示“登录后台发布”，改为注册环信平台导向
- 视频详情页底部 CTA 同步改为注册环信平台导向
- 开源项目详情页底部 CTA 同步改为注册环信平台导向
- CTA 点击时补统一前端埋点，并能区分具体点击位置

### 2.2 工程目标

在不新增后端接口和不引入新埋点 SDK 的前提下，先在 `ui-next` 内部建立统一注册跳转工具和统一点击事件出口。

工程约束：

- 第一阶段不改旧 `ui/`
- 第一阶段不新增后端埋点收集接口
- 第一阶段优先兼容已有全局分析脚本接管，而不是把埋点逻辑散落在多个组件里
- 第一阶段注册 CTA 跳转不能被埋点逻辑阻塞

## 3. 非目标

本规格不做以下事情：

- 不改管理员登录、后台发布和后台导航逻辑
- 不新增前台普通用户注册体系
- 不改首页其他运营位、Banner 或热门内容模块
- 不改 Footer、列表页卡片或弹窗中的外链口径
- 不把埋点扩展到所有外链点击

## 4. 现状确认

### 4.1 Header CTA 现状

当前 `ui-next/src/app/components/Header.tsx` 中有两处注册按钮：

- 桌面端右上角主按钮
- 移动端抽屉内“快捷操作”按钮

这两处当前都直接跳到未带参数的 console 注册地址，也没有统一埋点。

### 4.2 详情页底部 CTA 现状

当前 `ui-next/src/app/components/CtaBanner.tsx` 被以下页面复用：

- `ui-next/src/app/pages/ArticleDetail.tsx`
- `ui-next/src/app/pages/VideoDetail.tsx`
- `ui-next/src/app/pages/OpenSourceDetail.tsx`

当前逻辑仍按“管理员进入后台 / 游客登录后台发布”区分，不符合本轮“对外注册导流”的目标。

### 4.3 埋点现状

当前 `ui-next` 内没有现成的 CTA 埋点封装，也没有专门的注册跳转工具。

结论：

- 需要新增一个最小公共工具，统一承载目标地址和事件上报
- 页面组件只负责声明自己的点击来源，不再各自拼接链接和事件名

## 5. 关键边界

### 5.1 注册目标地址固定为带来源参数的 console 注册页

第一阶段统一使用：

- `https://console.easemob.com/user/register?from=community`

不允许：

- Header 和详情页使用不同注册地址
- 丢失 `from=community` 参数
- 局部页面继续保留旧的 `/admin/login` 或后台发布跳转

### 5.2 详情页底部 CTA 统一改为平台注册导流，不再按管理员态切换

第一阶段详情页底部 CTA 统一采用营销导向文案：

- 标题：`立即注册环信智能互动通讯云平台`
- 说明：`免费体验 · 支持 IM + AI + RTC · 一天快速接入 · 99.99%服务可用性`
- 按钮：`免费注册体验`

影响：

- `CtaBanner` 不再根据是否管理员切换到“进入后台管理”
- 详情页底部 CTA 统一承担外部注册导流职责

### 5.3 埋点事件统一为一个公共事件名，并带位置上下文

第一阶段统一收口为单一事件名，例如：

- `community_console_register_click`

事件至少应区分：

- Header 桌面端入口
- Header 移动端入口
- 文章详情页底部 CTA
- 视频详情页底部 CTA
- 开源项目详情页底部 CTA

如当前页面有内容上下文，可继续补充：

- 内容类型
- 内容 ID
- 内容标题

### 5.4 埋点实现优先做前端公共出口，不阻塞跳转

第一阶段优先原则：

- 优先复用页面当前点击动作，埋点为同步轻量上报
- 若全局分析脚本存在，则兼容 `dataLayer` / `gtag` 等常见入口
- 同时派发自定义浏览器事件，方便后续无侵入接入
- 如果分析脚本不存在，点击也必须正常打开注册链接

### 5.5 范围先收口到 `ui-next`

第一阶段只改：

- `ui-next/src/app/components/Header.tsx`
- `ui-next/src/app/components/CtaBanner.tsx`
- 详情页调用侧与公共工具

不改：

- 旧 `ui/`
- 后端 router / controller / service
- 站点配置和后台设置页

## 6. 验收标准

第一阶段完成后，应满足：

- 首页 Header 注册入口固定跳到带 `from=community` 的 console 注册页
- 文章、视频、开源项目详情页底部 CTA 文案全部更新
- 底部 CTA 按钮点击后固定跳到带 `from=community` 的 console 注册页
- 不同入口点击会产出统一事件名且可区分来源位置
- 埋点缺失或全局分析脚本不存在时，不影响链接正常打开
