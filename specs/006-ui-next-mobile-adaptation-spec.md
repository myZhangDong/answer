# 006 `ui-next` 移动端适配 Spec

## 1. 背景

当前 `ui-next` 已经承接内容门户前台主线，并且同时承载了新后台的页面实现。但现有页面结构整体仍然以桌面布局为主，移动端适配还不成体系，主要问题集中在以下几个层面：

- 公共壳层仍以桌面双栏为默认结构，`MainLayout` 依赖大屏左侧导航和较宽内容区
- 顶部 `Header` 在 `md` 以下只剩 Logo、主题切换和右侧操作入口，缺少成体系的移动端导航入口
- 首页、文章详情、视频详情、项目详情等页面普遍采用“主内容 + 右侧侧栏”的桌面排布，移动端需要重新收口
- Footer 仍存在 `whitespace-nowrap`、超宽 Logo、大行内链接等桌面表达，移动端容易拥挤或溢出
- 后台列表和编辑页虽然已有部分响应式类名，但仍存在 `grid-cols-2`、固定按钮区、桌面型信息密度等问题

从当前工程现状可确认：

- `ui-next` 已接入 Tailwind CSS v4，入口为 `ui-next/src/styles/tailwind.css`
- 大部分页面样式已经以 Tailwind 原子类组织，而不是独立 Sass / Less 方案
- 现有组件库中已引入 `sheet`、`drawer`、`dialog` 等可复用基础组件，可支持移动端菜单和浮层交互

因此需要拆出一份独立规格，明确：

- `006` 的目标不是“重做一套移动站设计”，而是在现有视觉语言下把 `ui-next` 做到移动端可读、可点、可完成主要路径
- 第一阶段优先利用 Tailwind 自带响应式断点、布局类和溢出控制完成兼容
- 前台内容门户需要达到完整可用，后台至少达到“手机上可操作、不中断”的基础可用状态

## 2. 目标

### 2.1 产品目标

让访客和管理员在移动端访问 `ui-next` 时，不再出现“只能看桌面页缩小版”的体验。

第一阶段必须满足：

- `ui-next` 前台首页、列表页、详情页、搜索页在移动端可正常阅读和操作
- 页面主流程不依赖桌面 hover、超宽容器或双栏固定布局才能完成
- 页面默认不出现全局横向滚动条
- 顶部导航、筛选、翻页、返回、互动、CTA 等关键动作在移动端可直接触达
- `ui-next` 后台在移动端至少可完成列表浏览、进入编辑页、保存表单等基础流程

### 2.2 工程目标

在不引入新样式体系、不重做整套组件库的前提下，让 `ui-next` 建立稳定的响应式基础。

工程约束：

- 优先使用 Tailwind CSS 原生响应式能力完成适配，例如 `sm:`、`md:`、`lg:`、`xl:`、`overflow-x-auto`、`flex-col`、`grid-cols-1`
- 只在确有重复模式时抽取少量复用组件或类名组合，不额外引入独立的移动端 CSS 文件体系
- 不新增第二套“移动端页面副本”，避免同一路由维护两份 DOM 结构
- 不新增设备检测库，不按 UA 分流页面

## 3. 非目标

本规格不做以下事情：

- 不重做 `ui-next` 的整体视觉风格
- 不单独开发一个 `m.` 域名或独立移动站
- 不把前台和后台全部改造成原生 App 风格交互
- 不在本轮引入新的 UI 框架替换 Tailwind 现有方案
- 不处理旧 `ui/` 的移动端适配
- 不在本轮承诺后台所有复杂页面都达到“移动优先精细运营台”的完成度

## 4. 现状确认

### 4.1 公共壳层与导航现状

当前 `ui-next` 公共壳层已存在明显的桌面优先倾向：

- `ui-next/src/app/components/MainLayout.tsx` 以桌面内容宽度和左侧导航布局组织页面
- `ui-next/src/app/components/LeftSidebar.tsx` 仅在 `min-[1200px]` 展示，移动端没有等价导航补位
- `ui-next/src/app/components/Header.tsx` 在 `md` 以下不展示主导航，在 `lg` 以下不展示搜索框，但没有完整移动菜单与搜索收口
- `ui-next/src/app/components/Footer.tsx` 使用了较宽 Logo、横向链接和 `whitespace-nowrap` 文案，不适合窄屏

结论：

- 仅靠“把侧栏隐藏掉”还不能视为移动端适配完成
- `Header / MainLayout / Footer` 必须作为第一批统一改造对象

### 4.2 前台内容页现状

前台内容页目前主要问题包括：

- 首页 `Home.tsx` 仍按主栏 + 右栏组织，右侧热门内容模块只在大屏出现
- 文章、视频、项目详情页均采用“正文 + 右侧辅助栏”布局，需要在移动端改为单列流式排布
- 列表页的筛选标签、统计信息、按钮、卡片信息密度偏桌面化
- 搜索页的 tab、结果块和多字段摘要需要重新约束窄屏信息层级

结论：

- 前台移动端适配不能只修容器宽度，还需要明确“侧栏下沉”“信息换行”“筛选滚动”“按钮堆叠”策略

### 4.3 后台页面现状

当前后台已有基础响应式处理，但仍未形成完整标准：

- `Admin.tsx` 已在 `md` 以下把侧栏改为横向滚动导航，但头部和内容留白仍偏桌面
- `AdminArticleEditor.tsx` 仍存在 `grid-cols-2` 默认双列
- `AdminArticles.tsx`、`AdminVideos.tsx` 等列表页以桌面卡片/操作区为核心，移动端信息和操作区容易拥挤
- `AdminProjectEditor.tsx`、`AdminVideoEditor.tsx`、`AdminSiteSettings.tsx` 等页仍有多列表单，需要明确折叠规则

结论：

- 后台第一阶段不要求每个页面都做重交互设计，但必须保证核心录入流程在移动端不断裂

### 4.4 Tailwind 基础现状

当前 `ui-next` 已具备 Tailwind 响应式改造的基础条件：

- Tailwind v4 已接入，无需额外安装响应式方案
- 现有代码已经大量使用原子类，改造成本主要在于布局收口，而不是技术栈切换
- 现有组件目录中已有 `sheet`、`drawer`、`dialog` 等基础组件，可优先复用

结论：

- 第一阶段默认选择“Tailwind 原生断点 + 少量复用组件”方案
- 不优先引入额外 CSS Modules 或自定义媒体查询体系

## 5. 关键边界

### 5.1 第一阶段采用 Tailwind 原生响应式策略

本规格第一阶段明确采用以下实现方向：

- 以移动端为默认样式基线
- 在 `md`、`lg`、`xl` 以上逐步增强为平板和桌面布局
- 优先通过 Tailwind 类名调整容器、栅格、间距、字号、溢出和显隐

不优先采用：

- 独立 `mobile.css`
- 基于 JS 的屏幕尺寸分流渲染
- 同一页面维护两套完整结构

### 5.2 前台完整适配优先于后台精细适配

第一阶段优先级明确如下：

1. 公共壳层
2. 前台首页、列表页、详情页、搜索页
3. 后台壳层和核心内容编辑页
4. 后台较低频页面的细节收口

这意味着：

- 前台页面应达到完整可用和视觉一致
- 后台页面第一阶段以“可操作、不断裂、不中断保存”为最低目标

### 5.3 有限允许局部横向滚动，但必须受控

第一阶段原则上不允许页面主容器出现全局横向滚动。

仅以下内容允许局部横向滚动：

- Markdown 代码块
- 表格类内容
- 横向筛选 chips
- 后台极少数无法压缩的字段组

要求：

- 局部滚动必须包在独立容器里
- 不能把整页横向滚动当作适配方案

### 5.4 不改变现有产品信息架构

本规格解决的是“如何在移动端展示和操作”，不是重做信息架构。

因此第一阶段：

- 不新增新的导航栏目
- 不改变内容门户三大栏目结构
- 不重定义后台菜单层级
- 不把移动端适配扩展成内容改版或视觉重设计任务

## 6. 范围

### 6.1 第一阶段必须覆盖的公共壳层

#### A. Header 移动端导航收口

要求：

- 在移动端提供明确的主导航入口
- 搜索入口在小屏下仍可触达
- 管理员入口和普通访客入口在小屏下都保持可点击
- 不依赖 hover 才能完成主要导航操作

推荐实现：

- 优先复用现有 `sheet` 或 `drawer` 组件承载移动导航
- 桌面横向导航继续保留在 `md` 或 `lg` 以上

#### B. MainLayout 单列化

要求：

- 小屏下默认改为单列内容流
- 左侧导航不可见时，主内容区域不应保留桌面空白
- 页面内主栏和侧栏在小屏下按顺序串行展示

#### C. Footer 收口

要求：

- Logo、品牌语、备案、链接、联系方式在移动端不溢出
- 长文案允许换行，不再强制 `nowrap`
- 联系方式与外链分组在小屏下纵向排列或分行排列

### 6.2 第一阶段必须覆盖的前台页面

#### A. 首页

要求：

- Banner、文章列表、标签筛选、热门内容模块在移动端单列可读
- 筛选标签支持横向滚动或换行，但不能挤压正文区域
- 右侧模块在移动端下沉到底部，而不是直接丢失高价值内容

#### B. 列表页

包括：

- 视频列表
- 项目列表
- 搜索结果页

要求：

- 卡片在移动端改为单列优先
- 元信息换行后仍保持阅读顺序清晰
- 筛选、tab、分页、查看更多按钮在单手操作下可点击

#### C. 详情页

包括：

- 文章详情
- 视频详情
- 项目详情

要求：

- 标题、作者、时间、浏览、点赞、评分、分类/标签在小屏下允许分组换行
- 右侧目录、热门教程、更多阅读等侧栏模块在移动端下沉到正文后
- 视频区域、封面图、CTA、点赞评分组件在窄屏下不溢出
- Markdown 内容中的代码块、表格、长链接保持受控溢出

### 6.3 第一阶段必须覆盖的后台页面

#### A. 后台壳层

要求：

- `Admin.tsx` 头部和导航在移动端不遮挡内容
- 小屏下后台导航可滚动或抽屉化，但必须可达
- 内容区留白按断点收缩，避免过度浪费横向空间

#### B. 后台列表页

包括：

- 文章管理
- 视频管理
- 项目管理
- 文章标签
- 用户管理

要求：

- 筛选区、按钮区在移动端改为上下堆叠
- 每个条目的标题、摘要、标签、操作按钮在小屏下保持层级清楚
- 删除、编辑、查看等关键动作不能因为窄屏被挤出可视区

#### C. 后台编辑与设置页

包括：

- 文章编辑
- 视频编辑
- 项目编辑
- 网站设置

要求：

- 默认双列表单在移动端折叠为单列
- Markdown 编辑器、预览浮层、媒体 URL 输入区和多字段分组在移动端不溢出
- 表单保存、返回、重置等主按钮在移动端有稳定位置

### 6.4 可以抽取的共享适配能力

第一阶段允许补充以下类型的共享能力：

- 公共页面容器断点规范
- 统一的移动端 section 间距和卡片内边距策略
- 统一的侧栏下沉模式
- 统一的移动端筛选 chips / tabs 滚动容器

要求：

- 优先使用 Tailwind 类组合或小型布局组件表达
- 避免为每个页面单独写一套适配逻辑

### 6.5 第一阶段不覆盖

以下内容不在 `006` 第一阶段交付范围：

- 旧 `ui/` 的移动端适配
- 独立的平板专用布局规范
- 复杂手势交互、下拉刷新、原生分享能力
- 后台复杂数据表的彻底重设计
- 针对每种设备单独定制视觉稿

## 7. 推荐实施策略

### 7.1 Phase A：公共壳层与高流量前台页面

优先顺序：

1. `Header`
2. `MainLayout`
3. `Footer`
4. 首页
5. 文章 / 视频 / 项目详情页

原因：

- 这些页面最直接影响移动端首屏可用性
- 壳层和详情页一旦收口，大部分页面的响应式模式会更清晰

### 7.2 Phase B：列表页与搜索页

优先处理：

- 视频列表
- 项目列表
- 搜索页

重点：

- 列表卡片栅格改单列优先
- tabs、chips、结果摘要和按钮行完成窄屏收口

### 7.3 Phase C：后台壳层和核心编辑流程

优先处理：

- 后台壳层
- 文章编辑
- 视频编辑
- 项目编辑

重点：

- 表单区从双列切单列
- 顶部操作区和底部保存区在移动端可达
- 列表页的筛选与操作区可点击

### 7.4 Phase D：回归与细节补强

补充检查：

- 暗色模式下的移动端可读性
- 长标题、长标签、长链接、空状态和错误提示的窄屏表现
- 代码块、表格、视频嵌入和弹窗的受控溢出

## 8. 验收标准

第一阶段建议至少按以下视口回归：

- 360px
- 390px
- 430px
- 768px
- 1280px

验收标准：

- 前台关键页面无全局横向滚动
- 顶部导航、搜索、内容筛选、返回、点赞评分、CTA 在移动端可用
- 详情页侧栏能力完成移动端下沉，不因隐藏而丢失关键内容
- 后台可在手机宽度下完成进入列表、打开编辑页、修改字段、保存提交
- 主要适配手段以 Tailwind 响应式类完成，而不是新增大段独立 CSS 覆盖
