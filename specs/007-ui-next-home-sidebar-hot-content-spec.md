# 007 `ui-next` 首页右侧“热门 Demo / 热门教程” Spec

## 1. 背景

当前 `ui-next` 首页右侧已经存在三块内容：

- 周热门文章
- 热门 Demo
- 热门教程

其中“周热门文章”已经接通真实文章列表，但“热门 Demo”和“热门教程”仍然是硬编码假数据：

- `ui-next/src/app/pages/Home.tsx` 里仍保留 `HOT_DEMOS` 常量
- `ui-next/src/app/components/SidebarWidgets.tsx` 里的 `HotTutorialsWidget` 仍写死教程标题
- `HotDemosWidget` 当前虽然支持传入 `demos`，但首页和项目详情页传入的仍然是静态数组
- `HotTutorialsWidget` 当前没有接收真实数据，也没有真实详情跳转目标

同时，当前后端能力并不完全对齐这次需求：

- 视频列表接口 `GET /answer/api/v1/video/page?order=hot` 已按 `view_count DESC` 排序
- 项目列表接口 `GET /answer/api/v1/project/page?order=hot` 虽然暴露了 `hot` 参数，但仓库实现仍按创建时间排序，不是真正的“按浏览量”
- 项目列表返回给前端的 `view_count` 目前来自关联 `question` 的浏览量，不是项目表自身独立字段

设计稿中首页右栏对这两块内容已经有明确表达：

- “热门 Demo”展示 2 条项目
- “热门教程”展示 4 条视频

因此需要拆出 `007` 独立规格，明确：

- 首页右栏两块内容的数据来源
- “热门”到底按什么排序
- 前端是复用现有列表接口，还是另起一个首页聚合接口
- 项目 `hot` 排序当前实现不符合需求时，第一阶段怎么修正

## 2. 目标

### 2.1 产品目标

让首页右侧“热门 Demo”和“热门教程”都展示真实内容，而不是静态占位文本。

第一阶段必须满足：

- “热门 Demo”展示开源项目，并按浏览量从高到低排序
- “热门教程”展示视频教程，并按浏览量从高到低排序
- 用户点击“热门 Demo”条目后进入对应项目详情页
- 用户点击“热门教程”条目后进入对应视频详情页
- 当数据为空、请求失败或返回不足时，首页布局保持稳定，不再回退到假数据
- 同轮将视频详情页、项目详情页右栏中的同类静态模块一起改为真实数据
- 继续保持 `006` 已确认的移动端下沉策略，不因为本次接线破坏首页响应式布局

### 2.2 工程目标

在不引入额外运营配置和不新建首页专用聚合接口的前提下，优先复用现有内容列表接口完成接入。

工程约束：

- 第一阶段不新增后台“手工置顶热门 Demo / 热门教程”配置
- 第一阶段不把点赞数、评分数混入热门排序
- 第一阶段优先复用现有 `project/page`、`video/page` 接口
- 如现有接口语义不满足需求，应先修正现有 `order=hot` 口径，而不是再造一套首页专用接口

## 3. 非目标

本规格不做以下事情：

- 不新增后台运营位去手工选择热门 Demo 或热门教程
- 不引入“浏览量 + 点赞 + 评分”的复合热度算法
- 不做个性化推荐或登录态推荐
- 不重做首页右栏整体视觉结构
- 不要求同轮改造旧 `ui/` 首页
- 不在第一阶段扩展为“首页右栏所有模块统一可配置”

说明：

- `SidebarWidgets` 是共享组件，如果实现过程中顺手消除详情页里的同类假数据，可以接受
- 首页仍是主验收页面，但视频详情页和项目详情页右栏同类模块也纳入本轮验收

## 4. 现状确认

### 4.1 前端现状

当前 `ui-next` 首页右栏实现存在以下事实：

- `Home.tsx` 右栏已经按“周热门文章 -> 热门 Demo -> 热门教程”组织结构
- “周热门文章”使用真实文章接口
- “热门 Demo”来自页面内 `HOT_DEMOS` 静态数组
- “热门教程”来自 `SidebarWidgets.tsx` 内部 `HOT_TUTORIALS` 静态数组
- `HotTutorialsWidget` 当前统一跳到 `/videos`，并没有逐条对应真实视频详情
- `HotDemosWidget` 当前只是展示数据卡片，首页里也没有真实项目详情跳转

结论：

- 当前右栏 UI 骨架已经存在
- 缺的不是布局，而是真实数据接入、点击目标和空态处理

### 4.2 视频后端现状

当前视频接口已经基本满足“热门教程”需求：

- 公开列表接口：`GET /answer/api/v1/video/page`
- 支持 `order=newest|active|hot|recommend`
- `hot` 在 `internal/repo/video/video_repo.go` 中已按 `view_count DESC` 排序
- 返回字段已包含 `id`、`title`、`view_count`、`cover` 等首页右栏所需最小信息

结论：

- “热门教程”第一阶段不需要新增后端接口
- 前端可直接复用现有视频分页接口，只需固定 `order=hot`

### 4.3 项目后端现状

当前项目接口只满足了一半：

- 公开列表接口：`GET /answer/api/v1/project/page`
- 接口参数已经支持 `order=hot`
- 响应里已经包含 `view_count`
- 但 `internal/repo/project/project_repo.go` 中 `hot` 分支目前仍按 `created_at DESC` 排序
- 当前项目浏览量来自关联文章 `question.view_count`

结论：

- “热门 Demo = 按浏览量排序”这个需求目前还没有真正落地
- 第一阶段必须先修正项目 `hot` 排序的真实语义，否则首页接了真实接口也仍然是错的

### 4.4 原型现状

根据 `ui-next/src/imports/环信开发者社区_原型图.html` 当前原型稿：

- “热门 Demo”区域展示 2 条项目
- “热门教程”区域展示 4 条视频
- 这两块内容都位于首页右栏
- 移动端下沉策略已在 `006` 中确认，不在本规格重定义

结论：

- 第一阶段默认按 `2 + 4` 的数量落地
- 后续如果要改数量，应作为单独产品调整，不在本规格里继续开放

## 5. 关键边界

### 5.1 热门排序口径只看浏览量

第一阶段明确采用以下口径：

- 热门 Demo 只按项目浏览量排序
- 热门教程只按视频浏览量排序
- 不引入点赞数、评分数、是否推荐等维度

推荐 tie-break 规则：

- 浏览量相同时，再按创建时间倒序

这样做的原因：

- `004` 已确认首页热门内容排序不引入评分
- 本轮目标是把现有“热门”从假数据切到真实数据，不适合再同时引入更复杂的热度算法

### 5.2 第一阶段复用现有列表接口，不新建首页聚合接口

第一阶段默认选择：

- 热门 Demo：复用 `GET /answer/api/v1/project/page?page=1&page_size=2&order=hot`
- 热门教程：复用 `GET /answer/api/v1/video/page?page=1&page_size=4&order=hot`

不优先新增：

- `/homepage/hot-content`
- `/sidebar/recommendations`
- 其他首页专用聚合接口

原因：

- 首页右栏只需要极小列表数据，当前已有分页接口足够承载
- 现在真正缺的是项目 `hot` 语义修正，不是接口数量不够
- 先复用现有接口可以减少 controller/service/schema 新增面

### 5.3 第一阶段数量按原型固定为 `2 + 4`

第一阶段默认值：

- 热门 Demo：2 条
- 热门教程：4 条

影响：

- 前端不需要做“查看更多”或翻页交互
- 请求参数可以直接收敛为小页长
- 如果接口返回不足，就按实际返回条数展示，不补假数据

### 5.4 点击行为统一进入详情页

第一阶段点击规则明确如下：

- 热门 Demo 条目跳转到 `/project/:id`
- 热门教程条目跳转到 `/video/:id`

第一阶段不选择：

- 热门 Demo 直接跳仓库外链
- 热门教程统一跳视频列表页

原因：

- 右栏热门模块属于内容发现入口，应优先进入站内详情页
- 这与当前首页热门文章的站内跳转语义保持一致

### 5.5 失败和空态允许降级，但不允许回退假数据

第一阶段容错原则：

- 请求失败时，不应阻塞首页其他区域渲染
- 请求为空时，不应继续显示静态占位条目
- 第一阶段默认展示轻量空态文案，不采用“直接隐藏整个模块”作为默认方案

最低要求：

- 不再使用 `HOT_DEMOS`、`HOT_TUTORIALS` 作为线上 fallback

### 5.6 详情页侧栏同类模块本轮一起收口

当前 `SidebarWidgets.tsx` 也被以下页面复用：

- `ui-next/src/app/pages/VideoDetail.tsx`
- `ui-next/src/app/pages/OpenSourceDetail.tsx`

第一阶段要求：

- 共享组件层改造成“外部传数据 + 外部传链接”
- 首页“热门 Demo / 热门教程”接入真实数据时，同轮同步替换视频详情页、项目详情页中的同类静态假数据
- 首页仍然是主验收页面，但视频详情页、项目详情页不再视为可选顺手项，而是本轮交付范围的一部分

说明：

- 本轮要求的是把同类静态模块改成真实数据，不要求为详情页再设计一套独立推荐算法
- 详情页可以继续复用与首页一致的热门口径和数据源

### 5.7 项目浏览量第一阶段继续复用关联文章浏览量

第一阶段确认如下：

- 热门 Demo 所依据的项目浏览量，继续复用关联文章 `question.view_count`
- 本轮不为项目表新增独立浏览量字段

原因：

- 当前公开项目列表返回的 `view_count` 已经来自关联文章浏览量
- 现阶段目标是先让“热门 Demo”排序口径正确可用，而不是重做项目浏览量模型
- 如果后续需要项目独立浏览量，应作为后续后端模型演进单独处理

## 6. 范围

### 6.1 本规格内必须覆盖的前端改造

#### A. 首页真实数据接入

至少覆盖：

- `ui-next/src/app/pages/Home.tsx`
- `ui-next/src/app/components/SidebarWidgets.tsx`
- `ui-next/src/app/api/contentApi.ts`

建议实现：

- 为热门 Demo、热门教程新增明确的数据读取封装，避免在页面里散落魔法参数
- 首页右栏与“周热门文章”并行加载，不相互阻塞
- 组件层支持接收真实条目数组和目标链接

#### B. 数据字段最小集

首页右栏第一阶段最少消费以下字段：

热门 Demo：

- `id`
- `title`
- `view_count`
- `cover` 或可降级占位图

热门教程：

- `id`
- `title`
- `view_count`

说明：

- 第一阶段不要求把作者、点赞、分类等元信息塞进首页右栏
- 右栏应保持轻量，不演变成列表页卡片压缩版

#### C. 响应式继承

必须继承 `006` 已确认策略：

- 桌面端仍位于首页右栏
- 移动端继续下沉到正文后
- 不因新增真实数据加载而破坏当前下沉顺序

### 6.2 本规格内必须覆盖的后端改造

#### A. 修正项目 `order=hot` 的真实语义

至少覆盖：

- `internal/repo/project/project_repo.go`
- 必要时补 `service/repo` 层的最小查询调整

第一阶段要求：

- 当 `order=hot` 时，项目列表必须按浏览量倒序返回
- 浏览量来源继续沿用当前关联 `question` 的 `view_count`
- 在浏览量相同情况下，按创建时间倒序稳定排序

说明：

- 第一阶段不要求为项目表新增独立浏览量字段
- 优先选择最小后端改动让现有接口语义变正确

#### B. 不强制新增控制器和 schema

如果复用现有接口参数即可达成需求，则不要求新增：

- 新 controller
- 新 schema
- 新 router

优先级：

- 先修正现有 `project/page` 的 `hot` 分支
- 再由前端消费既有公开接口

### 6.3 本规格第一阶段不覆盖

以下内容不纳入本轮交付：

- 后台配置“热门 Demo / 热门教程”手工置顶
- 首页右栏多语言运营文案配置
- 热门内容缓存层或排行榜离线任务
- 旧 `ui/` 首页同步改造

## 7. 推荐实施策略

### 7.1 先修后端语义，再接前端

推荐顺序：

1. 先修正项目接口 `order=hot`
2. 再在 `contentApi` 中补热门 Demo / 热门教程读取封装
3. 再替换首页右栏静态数组
4. 最后视情况收口共享组件在详情页中的同类假数据

原因：

- 如果先接前端，再修项目排序，首页会短期展示错误数据
- 先把接口语义修正，联调时更容易直接验收“热门 Demo 是否真的按浏览量”

### 7.2 前端优先做轻量封装，而不是首页里手写请求参数

建议新增或整理为明确语义的方法，例如：

- `fetchHotProjects()`
- `fetchHotVideos()`

目的：

- 避免 `Home.tsx` 里散落 `page=1&page_size=2&order=hot`
- 后续如果数量或排序口径调整，只改请求层

### 7.3 共享组件按“展示组件”收口

建议把 `SidebarWidgets.tsx` 收口为纯展示组件：

- 外部传入列表数据
- 外部传入条目链接
- 组件内部不再保留硬编码内容常量

这样做的好处：

- 首页、视频详情页、项目详情页可以共用一套 UI
- 假数据不会继续残留在组件内部

## 8. 验收

第一阶段完成后，至少应满足：

- 首页右栏“热门 Demo”展示真实项目，并按浏览量倒序
- 首页右栏“热门教程”展示真实视频，并按浏览量倒序
- “热门 Demo”数量默认为 2 条，“热门教程”数量默认为 4 条
- 点击热门 Demo 进入对应项目详情页
- 点击热门教程进入对应视频详情页
- 视频详情页右栏“热门教程”已切到真实数据
- 项目详情页右栏“热门 Demo”已切到真实数据
- 热门模块无数据时展示空态，不再隐藏为无内容区域
- 首页中不再依赖 `HOT_DEMOS`、`HOT_TUTORIALS` 静态数组作为正式数据来源
- 项目公开列表接口 `order=hot` 的语义与首页展示一致
- 移动端下沉布局不发生回归
