# 005 `ui-next` 内容标签与视频分类管理 Spec

## 1. 背景

当前 `ui-next` 管理后台已经具备文章、视频、项目三类内容的基础录入能力，但内容归类能力存在两个明显断层：

- 文章创建、编辑和列表筛选依赖后端已有标签数据
- 当前环境下文章标签选项为空，管理员无法在 `ui-next` 内补齐可用标签
- 视频创建、编辑和前台展示使用的是组件内硬编码分类，不是后台可维护配置

当前仓库内与本需求直接相关的现状是：

- 文章标签查询复用 `GET /answer/api/v1/question/tags`
- 后端已经具备标签新增、更新、删除、恢复接口，入口为 `/answer/api/v1/tag*`
- 文章创建和更新时会校验所选标签是否已存在，不存在会直接报错
- 视频当前使用独立的 `category/type` 字段，不走文章标签表
- `ui-next/src/app/pages/AdminVideoEditor.tsx` 当前仍在组件内写死 `VIDEO_CATEGORIES`

因此需要拆出一份独立规格，明确：

- `ui-next` 是否要增加“文章标签管理”页面
- 视频当前“分类”与文章“标签”是否属于同一模型
- “把视频现有硬编码分类抽出来，先做成可维护配置”这件事的边界到底是什么

避免后续一边实现标签管理，一边又误把视频分类强行并入文章标签体系，导致产品语义和后端模型都变得混乱。

## 2. 目标

### 2.1 产品目标

让管理员可以在 `ui-next` 中维护文章可用标签，并让文章录入、文章筛选与标签数据源保持一致。

第一阶段必须满足：

- `ui-next` 提供文章标签管理入口
- 管理员可以创建文章标签
- 文章创建、编辑页可直接选择已存在标签
- 文章列表标签筛选与文章编辑页使用同一套标签数据源
- 视频分类不再散落在页面组件内部硬编码
- 视频前台展示和后台编辑使用同一套分类配置来源

### 2.2 工程目标

在不重构现有文章和视频后端模型的前提下，先把“标签”和“分类”边界稳定下来，再逐步补后台维护能力。

工程约束：

- 文章当前仍复用 `question(content_type=2)` 链路
- 视频当前仍复用已有 `video.category/type` 字段
- 第一阶段不把视频分类并入文章标签表
- 第一阶段优先复用现有标签接口，不先新增一套标签后端模型

## 3. 非目标

本规格不做以下事情：

- 不重做文章后端模型
- 不把视频分类、文章标签、项目标签一次性合并成统一分类学系统
- 不要求第一阶段给视频增加“技术标签”
- 不要求第一阶段重构前台搜索的全部筛选维度
- 不要求第一阶段迁移旧 `ui/` 的全部标签相关页面
- 不在本轮定义“项目标签管理”

## 4. 现状确认

### 4.1 文章标签现状

当前 `ui-next` 文章链路已经绑定后端标签数据：

- 文章列表的标签筛选调用 `GET /answer/api/v1/question/tags`
- 文章创建、更新提交前，会先用标签查询接口校验标签是否存在
- 如果标签不存在，前端会直接报“标签不存在，请先选择后端已有标签”

结论：

- 文章标签不是 UI 本地概念，而是后端真实数据
- 如果后台缺少标签管理入口，`ui-next` 文章录入链路就不完整

### 4.2 后端标签能力现状

当前后端已经存在可复用的标签能力：

- `GET /answer/api/v1/question/tags`
  - 用于模糊搜索或选择已有标签
- `POST /answer/api/v1/tag`
  - 新增标签
- `PUT /answer/api/v1/tag`
  - 更新标签
- `DELETE /answer/api/v1/tag`
  - 删除标签
- `POST /answer/api/v1/tag/recover`
  - 恢复标签

结论：

- “文章标签管理”第一阶段不必先补后端新接口，优先复用已有标签接口
- 真正缺的是 `ui-next` 对这些接口的后台管理页与交互封装

### 4.3 视频分类现状

当前视频使用的不是文章标签模型，而是视频自身字段：

- 视频创建和编辑使用 `category`
- 视频列表与详情映射展示的是 `type/category`
- `AdminVideoEditor` 当前用组件内常量 `VIDEO_CATEGORIES = ["基础篇", "进阶篇", "群组篇", "AI篇"]`

结论：

- 视频当前是“单选分类”模型，不是“多选标签”模型
- 第一阶段不应把视频分类直接接到文章标签表

## 5. 关键边界

### 5.1 文章标签与视频分类不是同一概念

第一阶段明确区分：

- 文章使用“标签”
- 视频使用“分类”

这两个概念当前不做统一：

- 文章标签是跨文章内容的主题标识，可扩展、多选语义更强
- 视频分类是视频内容内部的栏目分组，当前是单选、固定集合语义

前台展示也继续区分：

- 文章卡片展示标签
- 视频卡片展示分类

### 5.2 “视频分类可维护配置”的边界

本规格对“把视频现有硬编码分类抽出来，先做成可维护配置”的定义如下：

第一阶段至少满足：

- 视频分类不再写死在单个页面组件里
- 必须有单一配置源，供视频前台和后台共同消费
- 新增、修改默认分类时，不需要进入多个页面逐个改常量

第一阶段默认不包含：

- 不默认承诺做“视频分类管理后台 CRUD 页面”
- 不默认承诺把视频分类落到文章标签表
- 不默认承诺给视频分类补独立数据库模型

也就是说，第一阶段“可维护配置”的最低含义是：

- 从“页面局部硬编码”升级为“集中配置 + 单一来源”

当前已确认第一阶段选择：

- 使用 `ui-next` 内部集中配置文件作为单一来源

不选择后端配置的原因：

- 当前视频记录本身已有 `category/type` 字段可用于展示和筛选
- 本轮目标是先去掉局部硬编码，不是补后台可编辑分类管理
- 在现有需求下，尚无必须由后台动态维护分类集合的明确约束

### 5.3 本规格第一阶段不做视频技术标签

如果后续希望视频也能按技术主题检索，例如：

- Web SDK
- Android
- React
- AI Agent

建议作为第二阶段新增“视频技术标签”能力，而不是复用当前视频分类字段。

这样可以避免把“AI篇”这种栏目分类和“React”这种技术主题混成一个字段。

## 6. 范围

### 6.1 第一阶段必须覆盖

#### A. `ui-next` 新增文章标签管理页

建议新增：

- 路由：`/admin/article-tags`
- 后台导航入口：`文章标签`

第一阶段必做闭环：

- 标签列表
- 创建标签
- 编辑标签
- 删除标签
- 在创建成功后，可立即回到文章创建页使用

如果复用后端现有能力，推荐同轮补齐：

- 恢复标签
- 标签描述维护

### 6.2 文章录入链路联动

文章相关页面需要统一到同一套标签源：

- 文章管理列表筛选
- 新建文章
- 编辑文章

第一阶段要求：

- 新建文章页可以明确提示“没有标签时先去标签管理创建”
- 如果本轮同时做路由联动，建议支持从文章编辑页跳到标签管理页，再返回当前页继续编辑

### 6.3 视频分类配置化

视频分类第一阶段只做“配置源收口”，不做模型统一。

要求：

- 后台视频编辑页从集中配置源读取分类选项
- 前台视频列表、详情若有分类展示，也使用同一配置源
- 默认值需要兼容当前线上已使用的分类名称，避免旧数据展示异常

建议保留当前默认集合，除非产品确认要改：

- 基础篇
- 进阶篇
- 群组篇
- AI篇

### 6.4 不在本规格第一阶段覆盖

以下内容先不纳入第一阶段交付：

- 项目标签管理
- 视频分类后台增删改页面
- 视频多标签能力
- 跨内容统一 taxonomy 后端模型
- 搜索页按统一 taxonomy 做高级聚合筛选

## 7. 推荐实施策略

### 7.1 文章标签管理策略

建议优先复用现有后端标签接口，前端只补最小管理页和 API 封装。

推荐顺序：

1. 新增 `ui-next` 标签管理服务封装
2. 新增 `ui-next` 文章标签管理页
3. 打通“创建标签后返回文章编辑页继续操作”的导航
4. 再补标签编辑、删除、恢复等增强能力

### 7.2 视频分类配置策略

当前已确认采用方案 A：仅集中到前端配置源。

确认原因：

- 当前视频记录本身已经包含 `category/type` 字段，可用于列表筛选和内容展示
- 本轮目标是先去掉局部硬编码，而不是补一整套视频分类后台管理
- 在现有需求下，没有证据表明视频分类集合必须经由后端动态维护

第一阶段落地要求：

- 把视频分类从页面组件局部常量抽到 `ui-next` 统一配置源
- 视频后台编辑页、前台展示页、筛选入口共同消费这份配置
- 若后续确认分类集合需要后台直接管理，再单独扩展为后端配置方案

## 8. 数据与展示规则

### 8.1 文章标签规则

第一阶段建议保持：

- 标签展示名称使用 `display_name`
- 查询和写入继续兼容 `slug_name`
- 文章创建至少要求选择一个标签

### 8.2 视频分类规则

第一阶段建议保持：

- 视频只允许单选一个分类
- 分类值直接映射当前后端 `category/type`
- 前台展示文案和后台选项文案一致

## 9. 风险与约束

### 9.1 不应把视频分类误接到文章标签表

如果直接把视频分类改成文章标签，会带来几个问题：

- 现有视频接口字段不是按多标签设计
- 前台视频展示语义会从“栏目分类”变成“主题标签”
- 后续如果再想补视频技术标签，会再次拆分模型

因此第一阶段应避免做这种看似统一、实际更混乱的改动。

### 9.2 文章标签管理可能受权限影响

后端标签新增、编辑、删除受权限控制。

这意味着：

- `ui-next` 新页面需要处理无权限提示
- 当前管理员账号是否默认拥有标签管理权限，需要联调确认

## 10. 已确认收口

本规格当前已确认以下收口结论：

- 视频分类第一阶段采用前端集中配置方案，不先做后端可编辑配置
- 文章标签管理第一阶段必须支持创建、编辑、删除
- 如复用后端现有标签能力，恢复标签和标签描述维护可以同轮补齐
- 视频默认分类第一版继续沿用现有四项：
  - 基础篇
  - 进阶篇
  - 群组篇
  - AI篇
